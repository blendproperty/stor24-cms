# Page SEO and redirects

Use Search & discovery → Page SEO for existing verified public pages. Choose the page, then set its search title, description and optional social title, description and approved media image. Blank fields retain website defaults. Save as Draft to review without changing the website; publish when ready. Published changes may take up to one minute.

Canonical page is for genuinely equivalent content. It must remain on an approved STOR24 page. Excluded canonical targets and chains are rejected. Exclude from search results removes the page from the sitemap and asks crawlers not to index it; the page stays publicly accessible. This is not a privacy control. Unpublish or remove a settings record to restore website defaults.

Use Redirects for retired public addresses. Enter the old and replacement STOR24 paths, choose permanent or temporary, review the destination and publish. Campaign query parameters, including repeated parameters, are preserved. External destinations, private/API/payment paths, current fixed pages, required legacy redirects, loops and excessive chains are rejected. Published articles and guides take priority over redirects; unpublish the old article before retiring its address. Check the replacement exists and meets the same need. Drafts have no routing effect. Unpublish a redirect to stop it.

Existing Articles and Storage Insights retain their publishing, SEO/image/FAQ and search-exclusion controls. Content Ideas remains a private planning workspace; an idea does not publish a public page. Search Console and Google tool links remain in Search & discovery. Google decides indexing and results; publishing does not guarantee either.

Structured data is generated automatically from the same published title, summary, image, dates and FAQ content shown on the website. Blog posts use BlogPosting and storage guides use Article; breadcrumbs follow the published address. A service or facility page retains its page identity when it also contains FAQs. The old guide schema-type selection is hidden because it was only a legacy reference and did not control the website; its stored values are retained without a migration. No raw JSON-LD editing is needed. When changing a slug, set up the appropriate redirect separately. Drafts are not public; search exclusion removes the page from the sitemap and prevents rich-result eligibility until indexing is enabled again.

Google retired FAQ rich results on 7 May 2026. Valid FAQ markup may still describe visible questions but is not a Google rich-result promise. Article author, store image/price range and other optional recommendations must use verified information; do not invent them to silence a warning. Check the published page with Google's Rich Results Test after significant edits. Automated production-build regression checks cover changed title, summary, image, dates, questions and slug, cleared optional fields, draft withdrawal and search exclusion.

Article and guide addresses accept lowercase letters, numbers and hyphens only. The CMS rejects spaces, uppercase letters, nested paths, queries and encoded paths before saving, matching the website schema route contract. A rejected edit retains the existing document. Changing a valid published slug still needs a reviewed redirect for the old address.

Micro Warehousing optional content must be a JSON object. Its faqs value is an array of non-empty question/answer text pairs, and facilities maps facility slugs to introductory text. Null or empty optional values can clear those sections. Invalid JSON shapes are rejected before save, preserving the previous content instead of breaking the visible page or its schema.
